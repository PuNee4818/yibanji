# 页面切换与登录状态排查

## 已修复的原因

- 游客提示曾直接出现在初始 HTML，等待登录脚本再隐藏。现在启用 JavaScript 时，在 head 内同步进入 pending 状态，确认会话后才展示对应入口；身份不可确认时提供重试，不假定为游客。禁用 JavaScript 时仍保留公开阅读和登录入口。
- 每页启动曾查询签到、管理员权限、个人资料与等级。签到与私人成长面板改为打开时请求；管理员权限只在菜单展开时查询。昵称、用户名和等级使用 5 分钟、按账号核对的 sessionStorage 显示缓存；不保存权限、私密内容或奖励余额。编辑资料强制刷新，签到事件更新等级，退出登录清除缓存。
- 并发初始化的会话读取合并为一次进行中的请求，完成后立即释放。缓存不承担鉴权，数据读写继续由 JWT、RLS 和 RPC 校验。历史恢复重新确认身份。
- 首页依赖的社区模块曾在顶层等待远程讨论请求，拖住同一入口的本机继续阅读、收藏显示。现在启动独立异步任务，慢讨论接口不阻塞这些功能。
- 投稿阅读原先等待正文和相关推荐两次串行请求。现在正文直接输出，推荐在接近视口时读取，失败可重试。公开作品仍使用 no-store，撤回规则不变。
- 作者主页的等级和文集关联查询改为并行；社区排行中的独立查询也改为并行。签到后的奖励页面复用已经返回的成长数据，避免立即重复查询。
- 收藏、历史初始显示读取状态，身份和数据确定后才判断空列表；不再先展示游客本机空记录，再替换成账号记录。
- 悬停、键盘聚焦与触摸预加载覆盖投稿广场及静态书房页面，只预取 HTML。作者个人页、投稿详情和带草稿参数的写作地址不预取，不提前执行阅读计数或互动。省流模式不主动预取。
- 页面交叉淡入缩短至 120ms，去除整页纵向位移；内容入场缩短至 220ms，保持系统减少动画偏好。预连接公开后端域名以减少首次连接等待。

## 同一流程的请求对比

本机生产构建、同一登录会话依次访问社区、投稿、奖励页；每页记录进入后 1.8 秒内的 REST 请求。第一次打开社区时没有身份显示缓存，后续跳转复用。数据只说明该流程的请求负担，不等同于公网响应时间提升比例。

| 页面 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 社区（首次访问） | 8 | 6 |
| 投稿（连续跳转） | 7 | 3 |
| 奖励（连续跳转） | 10 | 6 |

原始记录位于忽略提交的 `tmp/navigation-before.json` 和 `tmp/navigation-after.json`。

## 验证方式

- `navigation-performance.spec.ts` 延迟脚本下载，逐帧检测错误的游客提示；检查隐藏面板不抢首屏请求、奖励摘要不重复读取、退出清除身份显示缓存，以及预加载边界。
- `navigation-loading.spec.ts` 阻塞讨论接口，检查本机阅读记录和收藏仍能显示；验证禁用 JavaScript 的公开入口。
- 全站浏览器用例继续覆盖真实登录、修改资料、签到、书房、作品阅读、互动、发布、草稿恢复、移动端、暗色模式和可访问性。
- 类型、构建、样式审计和原文完整性检查。

开发服务包含模块转换、未合并的模块请求和热更新，体感不能直接作为线上构建的性能结论。动态内容仍需后端返回；本轮没有通过缓存私人数据、延迟撤回生效或减少权限校验来换取速度。

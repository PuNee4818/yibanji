# 一班集：体验审计与整体改造方案

日期：2026-09-21。本文件记录实施前审计；后续重构已完成，结果见 [重构验收记录](UX_REFACTOR_ACCEPTANCE_2026-09-21.md)。

## 1. 基线、范围与结论

- 当前基线：`c14b94ea`，提交说明 v0.92，main；审计开始时工作区干净。
- 历史基线：`40fb7b35`，提交说明 v0.5.1，即本次所指 v0.51；仓库没有同名 Git tag。
- 技术基础：Astro / TypeScript；文集静态生成；Supabase 提供账号、互动、社区和成长功能。
- 已审计当前导航、首页、目录、搜索、阅读器、社区、个人入口、样式、偏好与旧路由；逐项对照旧版搜索、正文渲染、目录树、沉浸模式、导出和首页。
- 已在本地实际浏览桌面 1440×1000、手机 390×844，以及日间和夜间页面。浏览器中检查的是访客体验；登录后的发布、关注、钱包和同步流程本轮以源码审计为主，未冒充实际操作验收。

总体判断：基础数据与互动能力应继续使用。体验问题集中在功能迁移不完整、信息层级过平、行动入口不足和阅读流程被打断。改造方向是“当代文学杂志”：以宋体、纸感、细线和少量朱红保留文集性格，以明确的操作层级、精致控件、合理留白和轻量动效提供现代体验。

## 2. 已确认的问题

| 优先级 | 问题与证据 | 对用户的影响 | 改造方向 |
| --- | --- | --- | --- |
| P0 | `search.astro` 只提交后检索；`search.ts` 不排序；索引缺 category | 搜索反馈弱，按卷找书失效 | 即时搜索、字段权重、卷目筛选、片段预览 |

| P0 | 社区访客发布区被隐藏，主内容没有登录参与入口 | 用户不知道下一步能做什么 | 常驻“写点感想”入口，访客看到登录参与说明 |
| P0 | 文章操作栏位于正文末尾，分享藏在“更多”，无 PDF | 长文中点赞、评论、分享成本高 | 桌面侧栏、手机底部工具栏，直接提供主要操作 |
| P0 | `site.ts` 把旧卷目链接转为 `?volume=`，目录页没有消费该参数 | 历史卷目链接不能正确定位 | 统一旧链接映射，定位卷目锚点 |
| P0 | 旧 `/resume` 被丢弃；旧字号、行距、版心键未转换 | 历史阅读位置和偏好体验断层 | 幂等迁移并保留旧数据备份 |
| P1 | 社区动态与文章评论共用朴素列表；引用文章卡片不足，举报与点赞同级 | 来源和主要动作不清楚 | 区分内容来源，突出回复/点赞，将管理操作收进菜单 |
| P1 | 移动端小说目录直接铺在正文前；首段距页面顶部约 639px（844px 视口） | 首屏阅读效率低 | 目录抽屉、紧凑篇头、首屏尽早出现正文 |
| P1 | 阅读页只有当前篇目录，短文左侧几乎空白；章间导航在评论之后 | 版面失衡，读完难以自然继续 | 本卷作品树；上一章/下一章放在正文结束与评论之间 |
| P1 | 当前夜间为偏绿黑背景、灰橄榄边线、浅桃色强调，表面层级少 | 页面发闷，操作与内容难区分 | 独立设计夜间语义色与层级 |
| P1 | 首字下沉、篇首序/题记的专门排版消失 | 文学内容的节奏被普通段落抹平 | 正文语义渲染，诗歌、题记、散文分别排版 |
| P1 | 当前 CSS 没有成体系的入场、切换或交互动画 | 状态转换生硬，缺少反馈 | 建立轻量动效规范，与键盘/减少动态效果兼容 |
| P1 | 首页续读和收藏预览消失；历史/收藏隐藏在头像菜单 | 回访者找回内容的路径变长 | 首页续读入口、“我的书房”明确可达 |
| P2 | 社区加载/失败多为一句文本，加载更多先递增页码 | 状态不明确；失败后重试可能跳页（源码风险，尚未网络故障复现） | 骨架、独立重试、成功后推进分页游标 |

搜索卷目复现：输入“故园”无法检出本卷 8 篇；“诗笺”无法检出本卷 9 篇。正文恰巧包含某卷名不等于支持卷目检索。

## 3. v0.5.1 功能对照清单

旧版搜索是文集内部多字段检索，涵盖篇名、作者、卷目、正文和小说章节文本；没有联网信息源、社区搜索或独立预览窗。必须准确区分恢复功能和新增能力。

## 4. 全站视觉、层级与动效

### 4.1 视觉语言

- 大标题与正文采用适合中文阅读的宋体体系；导航、数据、按钮使用清晰的无衬线体系。检查实际字体渲染与加载成本。
- 首页以刊头、主打作品、续读、卷目和社区回声形成主次；主动作突出“开始阅读/继续阅读”。
- 基础间距采用统一节奏，控制正文行长；边线用于分组，控件用适度圆角；浮层使用轻微阴影表达高于页面的层级。
- 纸张纹理只用于装饰层，强度低，不能干扰正文或增加明显资源成本。
- 明确 primary / secondary / quiet / danger 操作语义；登录、未读、选中、禁用、失败都有独立状态。

### 4.2 夜间模式初稿

| 语义 | 拟定起点 |
| --- | --- |
| 页面底色 | 墨黑 `#17191B` |
| 阅读/卡片表面 | `#202326` |
| 浮层表面 | `#292D31` |
| 正文 | 暖白 `#E9E4DA` |
| 次级文字 | `#B8B2A8` |
| 边线 | `#383D42` |
| 强调色 | 陶朱 `#D89883` |

这些是设计候选值，不是已经验收的最终色板。实施时逐对检查文字/背景、按钮文字、选中态和焦点对比度。纸色选择主要作用于日间阅读面，夜间使用单独校准的配色；导出固定采用浅色出版样式。保留跟随系统、手动选择、持久化和首次加载不闪白。

### 4.3 动效规范

- 悬停/按压：约 120–180ms；菜单/抽屉/预览：约 180–240ms；页面和章节转换：约 220–320ms。
- 优先 opacity / transform；列表错峰有总时长上限，只对首屏小批内容使用。
- 点赞与收藏使用短反馈，菜单有起止状态，翻章表现前进/后退方向。
- 正文默认可读，动画脚本失败不能使内容透明或不可访问；不使用每次进入都阻挡阅读的开场动画。
- 遵循 `prefers-reduced-motion`；键盘焦点不被过渡吞掉；网络慢与动画时长分开处理。

## 5. 页面结构与操作流程

### 5.1 导航与回访

主导航保持“首页 / 目录 / 社区”，全局搜索始终可见。“我的书房”汇集收藏、历史、个人主页和阅读设置；消息未读在外层可见；签到和奖励在社区/个人区域有明确入口。

首页依次为：刊头与阅读主入口 → 有记录时的继续阅读 → 主打与精选 → 卷目 → 精简收藏预览 → 社区回声。没有记录时自然折叠个人模块，不堆空白卡片。

访问链路统一：发现内容 → 看预览 → 阅读 → 评论/收藏 → 继续阅读。登录返回原页面、查询参数、锚点与待办意图；浏览器前进后退保留搜索和社区状态。

### 5.2 社区

桌面采用“主信息流 + 辅助侧栏”；中小屏合并，辅助信息不挡住动态。

- 页头直接说明“读一篇、聊两句、认识书友”，突出“写点感想”。访客点击进入登录且回到原任务；已有输入需保留本地草稿。
- 发布器平时紧凑，展开后显示输入区、字数、文章引用搜索、发布状态；发成功后能看见自己的内容或明确“查看刚发布动态”。
- 信息流保留热门/最新/关注；卡片明确区分“发布动态”“评论了某篇文章”，附文章引用卡。
- 主动作是回复、点赞和打开讨论；编辑、删除、举报在次级菜单；长内容适度折叠，时间显示友好且保留精确时间。
- 侧栏包含当前参与入口、本周热文、讨论入口与规则；奖励/鸡蛋能力保留为次级信息。
- 首次访问、关注为空、无搜索结果、加载失败各自提供可执行下一步；热门筛选仅过去七天，不能把热门无结果误写为整个社区没有内容。
- 分页失败可重试且不漏项、不重复；单一区块失败不能使整个社区空白。

### 5.3 搜索

采用“全局快捷搜索浮层 + 完整结果页”，共享检索和结果渲染逻辑。桌面结果列表旁可预览；手机打开可返回的预览层。浮层关闭回到触发处，预览不覆盖阅读进度。

恢复：即时输入、Ctrl/⌘+K、上下文片段、作者/卷目、收藏标记、相关度排序。

新增：关键词高亮、来源分组、筛选、键盘选择、章节/段落定位、搜索历史与清空、可分享查询 URL。

多来源分两层，均在本次计划内：

1. 本地文集：篇名、作者、卷目、正文、章节、小节、注释。输出精确命中类型、snippet、chapter、section/paragraph anchor 和稳定排序信息。
2. 社区公开内容：动态、文章评论、公开书友资料。使用受现有可见性规则约束的独立查询/RPC、分页和超时处理；隐藏/删除内容不进入结果。账号邮箱、钱包等私有数据不属于搜索源。

各来源独立加载；社区源故障时本地作品仍能完整搜索，并明确哪个来源不可用。中文检索先保证字面包含、短语和多词一致语义，再以实际规模评估索引；不直接假定默认英文全文检索可解决中文需求。

不在本次默认引入全网搜索。仓库旧版没有外部搜索来源，如后续扩展应先确定具体站点、接口和结果归属。

### 5.4 阅读器

桌面结构：左侧本卷/章节目录｜居中阅读版面｜右侧动作栏。空间不足时先收起目录，手机使用底部工具栏和目录抽屉。

- 右栏直接提供点赞、评论、收藏、下载 PDF、分享链接；阅读设置与专注模式容易唤出，臭鸡蛋保留明确次级入口。
- 同一操作只有一份状态来源，用响应式位置变化服务不同屏幕，避免桌面/手机按钮计数不同步。
- 篇头依次为位置、标题/副标题、作者与阅读信息，避免元信息占用太多首屏。
- 散文首段支持约 2–3 行的朱红首字下沉；处理开头引号/标点、题记和小标题，诗歌默认关闭；用户可关闭。
- 专门区分诗行、篇首序、题记、小节标题、正文、注释和署名日期。以元信息或集中规则识别，不改变原文字符串。
- 正文结束后先显示上一篇/下一篇或上一章/下一章，再进入评论和延伸阅读。
- 进度只覆盖正文；恢复位置优先使用稳定章节/段落信息，并兼容旧像素位置。登录云端进度与本地进度统一决策，避免先恢复一次又被覆盖跳动。
- 专注模式默认收起导航和社交内容，保留随时可唤出的设置与退出；Esc、触屏和键盘都能操作。
- 分享保持正确篇章/段落位置，复制失败有清楚替代路径。

### 5.5 PDF

目标是真正下载排版完成的 PDF，不能把“下载 PDF”只实现成打开系统打印对话框。

- 建议在构建/发布阶段从同一份正文模型生成 PDF，作为静态文件部署并缓存；实施首步验证中文字体、构建环境和生成时间，避免每次用户点击启动浏览器。
- 散文导出单篇；小说提供本章/全书。标题、作者、卷目、注释、落款和日期完整保留。
- A4 出版版式：合适页边距、中文字体嵌入、正文约 11–12pt、页眉页码、章节分页、标题与后文尽量同页、孤行控制。
- 导出使用单独样式，不包含导航、社区按钮、夜间背景或网站弹窗；文本应可选择和搜索。
- 生成失败需有可理解的重试/打印备用入口；失效链接不能显示成成功下载。
- 必须实际生成并渲染检查：短文、长散文、诗歌、带注释文章、小说单章、小说全书。检查页首/页尾、缺字、截断、空白页和文字完整性。

## 7. 代码落点与实现约束
